§ 01

System Overview & Vision

Insight is a role-based AI interview simulation platform designed to provide candidates with realistic, adaptive, and analytically rich mock interview experiences — without requiring human interviewers. The system addresses a critical accessibility gap: high-quality interview coaching has historically required costly human experts or employer-sponsored programs.

The platform accepts a candidate's resume (PDF) and a job description, then orchestrates an end-to-end interview session through a coordinated pipeline of four specialized LLM agents. Each agent has a distinct cognitive responsibility — behavioral profiling, response grading, question generation, and post-session feedback synthesis — mirroring the way real-world assessment panels divide evaluation labor.

Core Innovation: Rather than a single monolithic LLM prompt trying to simultaneously conduct an interview, score responses, detect behavioral patterns, and generate feedback, Insight decomposes these concerns into isolated, specialized agents. This enables deeper per-dimension reasoning and richer, more consistent output quality.

Problem Statement

Technical interviews at top companies demand preparation across multiple axes simultaneously — algorithmic fluency, systems thinking, behavioral communication, and role-specific domain knowledge. Existing preparation tools typically address only one axis (e.g., LeetCode for algorithms). Insight provides a unified, adaptive environment that evaluates all dimensions in a realistic conversational format.

§ 02

High-Level Architecture

The system is organized into three principal tiers: a browser-based single-page frontend, a Flask application server hosting the multi-agent orchestration logic, and a persistence/inference layer composed of Redis, ChromaDB, and the Groq inference API. Real-time streaming is achieved via WebSocket and Server-Sent Events (SSE) channels.

Graceful Degradation: Redis and ChromaDB are both optional. The application falls back to in-memory session storage if Redis is unavailable, and simply skips semantic context retrieval if ChromaDB is absent. This means the core interview loop runs with zero external infrastructure beyond a Groq API key.
§ 03

Multi-Agent System Design

The multi-agent architecture is the central architectural decision of Insight. Each agent is an independent class consuming a shared Groq client, with its own system prompt, evaluation schema, and output contract. The orchestrator in app.py sequences agent calls on each user response turn.

Agent Responsibilities

🧠

Profiler Agent

Analyzes behavioral patterns in each response. Detects persona archetype (confused, efficient, anxious, overconfident, chatty, silent, edge-case, normal), sentiment, and red flags like memorization or knowledge inconsistencies. Informs the Interviewer's adaptive strategy.

profiler.py · 244 lines · JSON output contract
📊

Grader Agent

Applies a weighted four-dimensional scoring rubric — Technical Accuracy (40%), Communication (25%), Problem Solving (20%), Relevance (15%) — against the current question, JD requirements, and candidate's resume. Maintains trend analysis across previous scores.

grader.py · 318 lines · score ∈ [0,100]
🎤

Interviewer Agent

The conversational core. Operates as "Byte", an elite senior technical recruiter persona. Generates contextually appropriate follow-up questions using profiler output, grader output, ChromaDB-retrieved context from the resume/JD, and the full conversation history. Streams token-by-token.

interviewer.py · 453 lines · SSE/WS stream
📋

Feedback Generator

Produces a comprehensive post-interview report on demand: executive summary, performance breakdown per dimension, STAR-method behavioral evaluation, technical competency map, and an ordered list of improvement recommendations with concrete action items.

Interview Phase Engine

The Interviewer Agent is governed by a five-phase state machine. Phase transitions are triggered by question_count thresholds, ensuring a structured progression from rapport-building through technical depth to behavioral exploration and finally to feedback synthesis.

PHASE 0
Introduction
Q0
PHASE 1
Technical
Q1 – Q3
PHASE 2
Behavioral
Q4 – Q6
PHASE 3
Deep Dive
Q7 – Q9
END
Feedback
Q10+

The Interviewer also adapts within phases based on the Profiler's persona detection. For example, an overconfident persona triggers deeper probing questions in the technical phase, while an anxious persona leads to more reassuring phrasing without reducing question difficulty.

Persona Archetypes: confused · efficient · chatty · edge_case · normal · silent · anxious · overconfident. The Profiler maps each user response to one of these archetypes with a confidence score, which the Interviewer uses to calibrate tone, follow-up depth, and pacing.

Context Retrieval via ChromaDB

Before each Interviewer call, the orchestrator performs a semantic similarity search against the session's ChromaDB collection. The collection contains chunked embeddings of the resume, the job description, and all previous Q&A pairs (added dynamically). The top-4 most relevant chunks are injected into the Interviewer's context window as a retrieval augmentation, enabling genuinely resume-aware questions.

# build_retrieval_context() called before each Interviewer turn def build_retrieval_context(session_id, query, top_k=4): collection = chroma_client.get_collection(f"session_{session_id}") results = collection.query( query_texts=[query], n_results=top_k, where={"session_id": session_id} ) return "\n".join(results["documents"][0]) # Injected into Interviewer system prompt as: # "RETRIEVED CONTEXT:\n{retrieval_context}"

Evaluation & Scoring Model

The Grader Agent applies a multi-dimensional weighted scoring model to each candidate response. Each dimension is independently evaluated by the LLM against explicit rubric criteria, then combined into a single 0–100 composite score.

Dimension Weight What Is Evaluated Rubric Band
Technical Accuracy
40%
 Factual correctness, use of correct terminology, absence of misconceptions 90–100: Flawless · 70–89: Minor inaccuracies · 50–69: Significant errors · <50: Fundamentally wrong
Communication
25%
 Clarity, structure, articulation, appropriate depth without verbosity Evaluated as a standalone quality score 0–100
Problem Solving
20%
 Approach methodology, edge-case consideration, creative alternatives, trade-off reasoning Evaluated as a standalone quality score 0–100
Relevance
15%
 Answer stays on-topic, directly addresses the question, aligned to role/JD requirements Evaluated as a standalone quality score 0–100

The Grader also maintains trend analysis across the session's all_scores list, detecting performance trajectories (improving, stable, declining) and applying stricter grading standards proportional to the declared seniority of the target role.

Composite Score Formula: score = 0.40 × technical + 0.25 × communication + 0.20 × problem_solving + 0.15 × relevance — all sub-scores in [0, 100]. The composite drives the real-time analytics chart in the frontend.

Security Architecture

The system's most distinctive security challenge is the sandboxed code execution environment for the coding challenge round. Python's exec() is used with a heavily restricted global namespace, preventing access to system calls, file operations, network access, or dangerous builtins.

# Sandbox: whitelist-only builtins safe_globals = { "__builtins__": { "range": range, "len": len, "int": int, "str": str, "list": list, "dict": dict, "tuple": tuple, "set": set, "bool": bool, "enumerate": enumerate, "zip": zip, "map": map, "filter": filter, "min": min, "max": max, "abs": abs, "sorted": sorted, } # No: open, __import__, exec, eval, os, sys, subprocess } exec(sanitized_code, safe_globals, {})
Session Isolation

Each user gets a UUID session_id. Redis keys are namespaced by session_id. ChromaDB collections are per-session. No cross-session data leakage is architecturally possible.

File Upload Safety

Only PDF MIME types accepted. File size limits enforced. Files are parsed in-memory and immediately deleted. No user-controlled file paths.

Credential Isolation

API keys loaded exclusively from environment variables via python-dotenv. Never hardcoded, never logged, never exposed via API responses.

TTL-Based Cleanup

Redis sessions expire after 6 hours (configurable). ChromaDB collections can be pruned on session end. Prevents indefinite PII retention.

Input Sanitization

All user inputs are validated before being passed to LLM prompts. Session IDs are validated format. No raw SQL or shell commands anywhere in the codebase.

Voice Privacy

Web Speech API processing occurs entirely within the browser. No audio data is transmitted to any server — only the transcribed text string.

§ 09

Scalability & Deployment

The architecture is designed for horizontal scalability. The application server is stateless per-request — all state lives in Redis. Multiple Flask instances can run behind a load balancer with WebSocket affinity, sharing a Redis cluster and ChromaDB persistence volume.

§ 10

Conclusion

Insight demonstrates that a thoughtfully decomposed multi-agent architecture produces qualitatively superior output compared to a single monolithic prompt. By separating behavioral analysis, response grading, question generation, and feedback synthesis into independent agents, each layer can be independently tuned, replaced, or scaled — a property that monolithic systems cannot offer.

The technology choices compound each other: Groq's inference speed makes streaming feel natural; Redis makes stateless Flask instances horizontally scalable; ChromaDB makes interviews genuinely resume-aware; vanilla JS makes the frontend lean and fast; and the Web Speech API adds voice capability at zero marginal cost.

Key Architectural Achievements: Real-time multi-agent orchestration with sub-second perceived latency · Safe Python code execution sandbox · Semantic retrieval-augmented interview personalization · Five-phase adaptive conversation engine · Graceful degradation — zero required infrastructure beyond a Groq API key.

Areas for Future Development

The current implementation has several clear extension vectors. A formal test suite (unit tests per agent, integration tests for the orchestration loop) would harden the system for production. Structured logging and observability tooling (Prometheus/Grafana) would improve operational visibility. The feedback generator could be extended with longitudinal tracking — comparing performance across multiple interview sessions for the same user. Finally, multi-language interview support could be achieved by parameterizing the agent system prompts.
